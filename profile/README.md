<p>把住宅代理接进自家后台，多数人卡在同一个地方：程序里能连通，业务跑一会儿就被拦。原因往往是只处理了网络这一层，出口、会话、业务三层各留了隐患。这篇按分层的方式来拆，四层分开看，每层说清它负责什么、常见的坑在哪、由谁来改。看完你大概能判断自己那套系统缺的是哪一层，而不是笼统地怀疑 IP。</p>

<h2>一、四层拆解总览：从网线到业务</h2>
<p>四层分别是网络接入、出口、会话、业务。网络接入决定流量从哪出去，出口决定外界看到你是谁，会话决定登录态存在哪，业务决定出错时怎么重试。四层里任何一层处理不当，表现都像「IP 被拦」，但改法完全不同。</p>
<h3>分层的好处是故障能定位</h3>
<p>不分层的时候，出问题只能靠猜，最常见的做法是换线，换完还不行就再换，一晚上换掉八条。分层之后判断就有顺序：先用命令行直连测通不通，再看出口归属对不对，再看登录态有没有串，最后看业务重试逻辑。四步走完，多数问题能落到具体一层。</p>

<h2>二、网络接入层：代理怎么挂进自家后台</h2>
<h3>三种挂法，各有适用场合</h3>
<p>一是环境变量，HTTP_PROXY 与 HTTPS_PROXY 配好即可，最快，但对不走系统代理的库无效；二是网关转发，把出口收敛到一台内网网关，业务代码不用改，适合已有多个服务的情况；三是 SDK 或客户端参数，代码里显式指定，可控性最好，缺点是每处调用都要改。小团队建议先用环境变量验证，稳定后再收口到网关。</p>
<h3>挂上去之后要验的三项</h3>
<p>第一项，出口真的换了吗？用 curl -s https://ipinfo.io/ip 打一次，和本地公网 IP 对比，别只看程序没报错。第二项，DNS 解析走哪？很多库会绕开代理自己解析，结果出口在 A 国、解析在 B 国。第三项，超时设置合不合理，代理链路比直连多一跳，原来三秒的超时要放宽到八到十秒，否则大量误判为失败。</p>

<h2>三、出口层：双 ISP 的切换逻辑</h2>
<p>原生家宽双 ISP 的意义在于，一条线出问题时能立刻换另一家运营商，而不是换一个同运营商的相邻段。同段相邻，风控视角里几乎是同一个地方；换运营商，才算真的换了出口来源。</p>
<h3>主备判定条件要写死</h3>
<p>建议只用三个客观条件触发切换：连续三次探测失败、丢包率超过 5%、首包延迟超过 800 毫秒。不要用「感觉慢」当条件，那会让切换变得随机，切换本身也是变更，频繁切换比慢一点更伤。</p>
<h3>切换时不要动的参数</h3>
<p>时区、语言、分辨率、浏览器版本一律不动，只换出口 IP。很多接入方案图省事，切换时连带重建了容器，参数跟着变，等于一次做了两个变更。判断标准很简单：切换前后用同一份配置指纹比对，除了 IP 之外应该完全一致。</p>

<h2>四、会话层与业务层：登录态谁来保存</h2>
<h3>会话层：把登录态从代码里拿出来</h3>
<p>常见反模式是把 Cookie 存在进程内存或全局变量里，多任务并发时互相覆盖，于是出现 A 任务的请求带着 B 任务的登录态发出去。改法是把会话按账号维度存到独立目录或独立键空间，任务启动时加载对应那一份，用完写回。这一层不改，换多少条线都没用。</p>
<h3>业务层：重试要退避，操作要幂等</h3>
<p>失败重试是必要的，但要有三条约束：指数退避，首次间隔两秒、逐次翻倍、上限一分钟；同一账号的并发不超过设定值；重试前判断操作是否已经生效，避免重复提交。很多「被拦」其实是自己的重试把并发打满了，服务端只是正常限流。</p>
<h3>日志留什么，出问题才查得动</h3>
<p>每次请求记四项：账号标识、使用的出口 IP、开始与结束时间、响应码。四项凑齐，事后能画出「哪个号在哪个出口上被拒了几次」的图。没有这四项，只能凭印象判断，而印象在多人协作里几乎不可靠。</p>

<h2>常见问答</h2>
<h3>接入之后程序变慢，是代理的问题吗？</h3>
<p>答：先看是不是超时设置没放宽导致重试变多。代理多了一跳，原来三秒超时的请求会被反复中断重发，看起来像慢。把超时调到八秒以上再测一次，多数情况会恢复正常。</p>

<h3>双 ISP 真的有必要吗，单条好线不行？</h3>
<p>答：看中断代价。内部系统偶尔断几分钟能接受，单条够用；跑长任务或对外提供服务，双 ISP 的价值在切换那几分钟里体现，平时看不出差别。</p>

<h3>能不能多个账号共用一条独享线？</h3>
<p>答：技术上能，业务上不建议。共用出口等于把几个号绑在一个网络身份上，一个出问题其他跟着受牵连，省下的那条线钱通常不值得。</p>

<h3>服务端返回限流，是不是该马上换 IP？</h3>
<p>答：不该。先降并发、加退避，观察十分钟。如果降速后恢复正常，说明是频率问题；如果降速后仍被拒，再查出口是否被整段限制，这时换线才有意义。</p>
